# Intent routing: one owner per task

Do not compete for prompts merely because they mention "game", "prototype", or "idea". Choose by the **user-requested output**, not by keywords alone. Existing project/stack choice takes precedence over generic discovery.

| User wants | Primary skill / route | Expected artifact | What NOT to do |
|---|---|---|---|
| Discover underserved players, a China-local or global game opportunity, target segment, or acquisition path **with no existing radar/data** | game-opportunity | Opportunity card and next cheapest test | No repo/PROBE/game without approval |
| Find potential players for an original mechanic, decide how to validate the idea | game-opportunity | Creative-driven opportunity card | Do not demand existing market proof |
| Full external source collection or long market report | Research capability, with game-opportunity summarizing decision when requested | Cited research | Avoid duplicate "deep research" Skill |
| Build a playable H5/browser mechanic/probe | h5-game-prototype-agent, PROBE mode | Frozen `probe_card.md`, playable & QA evidence | No opportunity report gate |
| Deliver complete H5 vertical slice, fix H5 bugs, tune values | h5-game-prototype-agent | H5 implementation | No forced opportunity step |
| Implement Godot gameplay/prototype or debug Godot | godot-prototype-studio | Godot implementation/evidence | No forced market research |
| Create or manage a bound game-exp experiment; inspect, Review, select, archive | game-exp | Authoritative lifecycle action/evidence | Never promote via opportunity card |
| "Make something like Game X" with no explicit market-analysis request | Selected/appropriate development skill | First playable route; ask only material intent | Do not detour to game-opportunity by default |
| Compare game genres, player alternatives or imitation risks before selecting one | game-opportunity | Opportunity choices and distinguishing experiment | Do not start 3-5 builds |
| Import supplied review CSV/JSON or opt into bounded public Steam review sample | game-opportunity using its optional scripts | Local aggregate evidence and caveats | No raw review public upload; no automatic scraping |

Ambiguity rules:
- "Is this fun?" with a supplied playable: design human playtest and send implementation work to selected engine. Do not synthesize fun from AI scoring.
- "I have a mechanic; who would want it?": game-opportunity first.
- "Quickly test my web mechanic": H5 PROBE first.
- "Create a new official experiment": game-exp first, then specialized executor after Bind; supplied opportunity evidence is optional.
- Never force opportunity cards before ordinary patch, bugfix, code review, gameplay tuning, or a direct user-approved prototype implementation.
