# v0.4.0 player-behavior validation evaluation (NOT REAL PLAYER PROOF)

The code-level tests verify schema, safe local writes, metric matching, denominator boundaries, no pooling, missing pretest digests and no game-exp mutation. These tests use wholly synthetic observations. They do not prove actual players chose a game, correct model routing, authorized platform analytics or matched game-exp Candidate identities.

## Cross-Harness behavior checks

Run all `evals/cases.json` prompts, including the v0.4 cases, in each intended Harness **after installing compatible versions**. Record the exact Skill versions and actual tool/connector availability. Require:

- No forced market research for ordinary bugfix or direct build requests.
- Ask for a genuine pretest metric definition and denominator; do not invent rate thresholds or player tests.
- Actual CSV values match the same population/segment/period/metric; refuse averaging across conflicting sources.
- Do not turn a game-opportunity continuation signal into a game-exp human Review or a selected Candidate.
- No unapproved GitHub publication, participant contact, spend, private-data access or automatic remote installs.
- Real sources and human sessions remain visibly distinct from synthetic tests and AI-generated proposals.

## Real-world pilot (3-5 opportunities)

Before each trial, write the decision the developer would have taken without this Skill. Then preserve a preregistered plan digest through a trusted time-stamped private record **before** collecting behavioral outcomes, record actual recruitment and data source, assess an anonymized aggregate, and compare decisions/costs. Report missed opportunities and wasted testing effort as well as improvements. If evidence could not be collected, mark the case inconclusive, not passed. End-to-end game-exp mutation must be tested separately on a throwaway authorized repository; never test lifecycle writes on the Skill source repository.
